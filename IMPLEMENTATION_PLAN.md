# Dancing Cats — план и устройство реализации

## 1. Цель текущей версии

Расширение Chromium 116+ накладывает прозрачный WebM с танцующими котами на обычные видео YouTube и Shorts. Основной режим обращается к локальному backend: All-In-One заранее размечает beats, downbeats и музыкальные секции всей композиции, после чего планировщик строит законченную хореографию. Захват звука вкладки используется как fallback, пока карта готовится или backend недоступен.

Алгоритм не выбирает случайные кадры. Каждый фрагмент движения всегда проигрывается вперёд и непрерывно; меняется только скорость между соседними визуальными якорями.

## 2. Что реализовано

- Manifest V3 и разрешения `tabCapture`, `offscreen`, `storage`;
- локальный FastAPI backend с yt-dlp, FFmpeg и All-In-One;
- асинхронные задания анализа и файловый JSON-кеш без сохранения аудио;
- заранее рассчитанные cues, привязанные к `currentTime` YouTube;
- зеркалирование на границах движений и масштабный импульс на каждом beat;
- один активный захват вкладки и возврат звука на аудиовыход;
- spectral flux detector с оценкой BPM, фазы, confidence и энергии;
- устойчивые музыкальные часы с плавной коррекцией фазы и темпа;
- motion map с сегментами, позами, интенсивностью и beat/time-якорями;
- граф переходов между законченными движениями;
- выбор следующего совместимого движения по позе и энергии музыки;
- линейный time warping между якорями с ограничением скорости;
- crossfade только для разрывных переходов по таймлайну ассета;
- остановка вместе с YouTube, сброс анализа после seek и SPA-навигации;
- ручное перетаскивание и масштабирование оверлея;
- отдельный каталог расширяемых ассетов и карт;
- структурный валидатор manifest, каталога, карт и WebM.

## 3. Поток данных

```text
клик по action
    │
    ▼
service worker ── stream id ──▶ offscreen document ──▶ local backend
    │                              │
    │                              ├─ AudioContext → speakers
    │                              └─ AnalyserNode → BeatDetector
    │                                             │
    ◀──── live rhythm fallback / choreography map ──┘
    │
    ▼
content script → BeatClock → MotionPlanner → два video-слоя overlay
                              ▲
                 catalog → motion-map.json
```

### Service worker

`extension/background.js` запускает и останавливает захват, создаёт offscreen document, хранит активный `tabId` в `chrome.storage.session` и маршрутизирует результаты анализа. Повторный клик выключает оверлей и освобождает поток.

### Offscreen document

`extension/offscreen.js` получает аудиопоток через `getUserMedia`, подключает его одновременно к выходу и `AnalyserNode`, а затем каждые 25 мс передаёт спектр детектору. Сырые PCM-данные не сохраняются и не покидают браузер.

### Beat detector и музыкальные часы

`extension/beat-detector.js` вычисляет положительный spectral flux в диапазоне 35–3000 Гц, выделяет onset-события и строит гистограмму кандидатов темпа 70–180 BPM. Фаза оценивается круговым усреднением onset-событий.

Детектор отправляет новое состояние раз в 100 мс. `BeatClock` в content script непрерывно интегрирует позицию между сообщениями, сглаживает период и небольшими поправками удерживает фазу. Это исключает скачки при уточнении BPM.

### Motion planner

Планировщик получает непрерывный номер музыкального удара. Внутри текущего segment он находит два соседних anchor и переводит музыкальную позицию во время WebM. Скорость между anchor рассчитывается так:

```text
playbackRate = sourceDuration / musicDuration
```

Итоговое значение ограничено диапазоном 0,55–1,8. Небольшая обратная связь по ошибке `currentTime` компенсирует задержку декодера; seek применяется только при заметном рассогласовании.

На границе segment планировщик:

1. исключает немедленный повтор текущего фрагмента, если есть альтернативы;
2. выбирает ближайшее движение по энергии музыки;
3. использует `next` и совместимость поз как мягкие штрафы, а не как жёсткое ограничение;
4. продолжает движение вперёд с начала выбранного segment;
5. включает crossfade, если исходные диапазоны WebM не соседние.

Для текущих трёх котов это намеренно нарушает исходный порядок ролика: спокойные и энергичные секции получают разные чередования фрагментов. Новые ассеты могут иметь несколько вариантов одного движения для низкой, средней и высокой энергии.

## 4. Пространство ассетов

```text
extension/assets/
├── catalog.json
└── cats/
    ├── three-cats/
    │   ├── video.webm
    │   └── motion-map.json
    └── <new-asset>/
        ├── video.webm
        └── motion-map.json
```

`catalog.json` задаёт доступные наборы и default asset. Пути разрешаются относительно файла, в котором указаны, поэтому папка персонажа переносима как единое целое.

Текущая карта делит 11,8 секунды на три непрерывных движения по восемь ударов: `front-wave`, `side-sway` и `turn-return`. Для каждого движения размечены диапазон исходного времени, музыкальная длина, энергия, теги, входная/выходная поза, допустимые переходы и визуальные акценты.

Подробная схема и инструкция по добавлению набора находятся в `extension/assets/README.md`.

## 5. Состояния и поведение

- До накопления минимум шести onset-событий ассет проигрывается с исходной скоростью.
- При confidence ниже 0,24 синхронизация не применяется.
- При устойчивом ритме включаются музыкальные часы и motion planner.
- Pause останавливает оба слоя котов.
- Resume продолжает текущий план, если захват не сбрасывался.
- Seek, загрузка нового media и переход YouTube сбрасывают детектор, часы и граф движения.
- Если backend недоступен, badge показывает `RT`, но live beat detector продолжает менять фрагменты, зеркалирование и масштабные импульсы.
- Положение и масштаб сохраняются локально. Других пользовательских настроек нет.

## 6. Добавление нового персонажа

1. Подготовить WebM VP9 с alpha channel, без аудио.
2. Выделить законченные движения и отметить их границы.
3. Для каждого движения определить число ударов и визуальные акценты.
4. Назначить `entryPose`, `exitPose`, `energy`, `tags` и `next`.
5. Убедиться, что переходы по позе выглядят естественно.
6. Добавить карту в каталог.
7. Выполнить `python3 tools/validate_extension.py`.
8. Проверить набор на треках с разным BPM и уровнем энергии.

Для богатого графа рекомендуется иметь хотя бы по два варианта движения для каждой основной позы и диапазона энергии. Нейросеть во время работы расширения не требуется: сложное понимание исходного танца переносится на этап разметки, а real-time часть решает только задачу выбора и time warping.

## 7. Проверка перед выпуском

Автоматические проверки:

```bash
python3 tools/validate_extension.py
bash -n tools/assets/process-cats.sh tools/assets/process-reference-cats.sh
```

Ручная матрица:

- `/watch` и `/shorts`;
- музыка 70–180 BPM, речь и тишина;
- pause/resume, seek и смена ролика;
- последовательное переключение между Shorts;
- обычный и полноэкранный режим;
- drag/resize и повторная загрузка страницы;
- включение, выключение и повторный запуск захвата;
- сохранение слышимого звука вкладки;
- визуальная проверка всех переходов карты.

## 8. Следующие улучшения

1. Добавить инструмент полуавтоматической разметки: optical flow предложит пики движения и границы, а человек подтвердит anchors и poses.
2. Добавить несколько движений на одну позу, чтобы `energy` реально давала заметное разнообразие.
3. Ввести downbeat/размер такта и выбирать длинные движения только на границе музыкальной фразы.
4. Добавить hysteresis к выбору энергии, чтобы пограничные значения не чередовали варианты.
5. Сделать диагностический режим разработчика вне пользовательского интерфейса: BPM, confidence, текущий segment и phase error.
6. Провести длительные browser-тесты и профилирование CPU на слабых устройствах.
7. Перед распространением подтвердить лицензию видеоассета или заменить его собственным.
